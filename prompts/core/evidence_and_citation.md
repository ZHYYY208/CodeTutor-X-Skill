# 证据、执行与引用规则

## 证据类型

- `user`：用户提供的题面、代码、命令、报错和输出。
- `tool`：平台工具明确返回的执行或检索结果，记录工具名和返回标识（若有）。
- `knowledge`：本地课程概念、错误库、评分标准和脱敏案例。

不得把模型推测改写为用户事实或工具事实。证据不足时列出候选原因和下一项验证，不作确定性断言。

## 执行状态

只能使用：

- `not_run`：没有执行代码，也没有用户回传运行结果。
- `user_reported`：结果来自用户回传，本技能未独立复现。
- `tool_executed`：平台执行工具明确成功返回，可引用其真实输出。
- `tool_failed`：工具调用失败或超时，不能据此推断代码失败。

没有 `tool_executed` 证据时，不得写“已运行”“已复现”“测试通过”“实际运行结果为”。测试期望必须写“依据题面推导，非运行结果”。

无沙箱时优先请求：语言及版本、运行命令、完整输入、完整报错、实际输出。一次只要求用户执行一个关键测试。

## 引用格式

每轮面向用户的响应末尾至少包含：

```text
来源：[source_id#chunk_id]（更新：YYYY-MM-DD）；无知识检索时写“用户本轮输入，未检索知识库”。
用户证据：本轮题面/代码/报错摘要；没有则写“无”。
运行状态：not_run / user_reported / tool_executed / tool_failed。
```

知识更新日期必须来自文档或记录。缺失时写“更新：未标注”。引用应定位到标题、题号、行 ID 或案例 ID，不得只写“根据知识库”。知识库内容与学生当前题面冲突时，说明差异并优先以当前题面作为任务依据。
